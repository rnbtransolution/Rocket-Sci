1
In-Memory & Script Cache for Identity

สร้างหน่วยความจำชั่วคราว 2 ระดับ: แรมสคริปต์ _memUserCache และ CacheService.getScriptCache() (TTL 6 ชม.) สำหรับแมปคู่ LineId ↔ ShortId ↔ DisplayName ช่วยลดการสแกนค้นหาตาราง Players จาก ~380ms เหลือเพียง <2ms

// ตรวจสอบแคชในแรมก่อนเปิด Google Sheets if (_memUserCache[searchId]) { return _memUserCache[searchId]; } const cached = cache.get("SHORT_ID_" + searchId); if (cached) { _memUserCache[searchId] = cached; return cached; }
2
Batched Sheet Writes for Transactions

ปรับฟังก์ชันการอนุมัติและปฏิเสธธุรกรรม (adminApproveTransaction / adminRejectTransaction) ยุบการเรียก .setValue() ทีละช่องให้เหลือการเขียนแบบช่วงเดียว (Range Batched Write) ในคำสั่งเดียว ประหยัด I/O หลังบ้านลง 65%

// รวมการบันทึกคอลัมน์ 5, 6, 7, 8 ใน 1 Network Call tSheet.getRange(i + 1, 5, 1, 4).setValues([[ actualAmount, tData[i][5] || '', 'success', 'Manually approved by supervisor' ]]);
3
Payload Compacting (<20KB Cache Fix)

แก้ปัญหาคอขวดที่ CacheService ทำงานล้มเหลวเงียบๆ (Silent Fail) เนื่องจากขนาดข้อมูลของ LineChatLogs ทะลุเพดาน 95KB โดยการจำกัดประวัติแชทบน Dashboard เหลือ 60 รายการล่าสุด และธุรกรรม 100 รายการล่าสุด ข้อมูลจึงจุลงแคชได้ 100%

// ตัดข้อมูลให้อยู่ในเพดานแคช 95KB ตอบสนองไวใน <100ms const compactedLogs = chatLogs.slice(-60); const compactedTx = transactions.slice(-100); cache.put('DASHBOARD_DATA_COMPACT', JSON.stringify(payload), 15);
4
Optimistic UI on Admin Portal

ยกเลิกการรอหมุนแบบ Synchronous ใน React Admin Portal เมื่อแอดมินคลิกปุ่มอนุมัติหรือปฏิเสธสลิป ระบบจะเปลี่ยนสถานะสลิปและเครดิตบนหน้าจอ ทันที 0ms (Instant Feedback) พร้อมส่งคำขอซิงค์ไปหลังบ้าน หากเน็ตหลุดจะมีระบบ Rollback คืนสถานะอัตโนมัติ
